Review 08 · Information Extraction

Document Intelligence (layout/prebuilt/custom) vs Content Understanding (đa phương thức: doc/audio/video/image, analyzer + schema, extract/generate/classify). Ôn nhanh + bẫy thi.

Document IntelligenceContent Understandingprebuilt vs customMultimodal

1. Tóm tắt

  • Document Intelligence (cũ: Form Recognizer, SDK azure-ai-formrecognizer → azure-ai-documentintelligence) = chỉ tài liệu. Gọi begin_analyze_document(model_id, ...).
  • Models DI: prebuilt-layout (trang/đoạn/bảng/toạ độ) · prebuilt-invoice, prebuilt-idDocument (field chuẩn hoá + confidence) · custom (train model riêng theo mẫu form).
  • Content Understanding (mới, GA 2025) = đa phương thức: document/audio/video/image dùng chung 1 API begin_analyze(analyzer_id, ...), chỉ đổi analyzer.
  • CU analyzer: prebuilt (vd prebuilt-documentSearch, prebuilt-audioSearch, prebuilt-videoSearch) hoặc custom với schema field tự định nghĩa (begin_create_analyzer).
  • 3 kiểu field trong CU schema: extract (lấy giá trị có sẵn) · generate (model sinh/suy luận giá trị) · classify (phân loại).
  • Tất cả đều long-running (poller). CU trước có SDK phải gọi REST tay — nay dùng azure-ai-contentunderstanding.

2. Cú pháp cần nhớ

# DOCUMENT INTELLIGENCE — layout (bảng/cấu trúc):
from azure.ai.documentintelligence import DocumentIntelligenceClient
poller = client.begin_analyze_document("prebuilt-layout", body=f)
result = poller.result()
for table in result.tables:      # cells + bounding regions
    ...

# DI — prebuilt field có confidence (đổi model_id):
client.begin_analyze_document("prebuilt-invoice", body=f)       # VendorName, Total...
client.begin_analyze_document("prebuilt-idDocument", body=f)    # field + .confidence

# CONTENT UNDERSTANDING — chung 1 API, đổi analyzer_id cho mỗi modality:
from azure.ai.contentunderstanding import ContentUnderstandingClient
poller = client.begin_analyze(analyzer_id="prebuilt-documentSearch", ...)  # document
poller = client.begin_analyze(analyzer_id="prebuilt-audioSearch", ...)     # audio
poller = client.begin_analyze(analyzer_id="prebuilt-videoSearch", ...)     # video

# CU — custom analyzer với schema (extract/generate/classify):
analyzer_definition = { "fieldSchema": { "fields": { ... } } }  # mỗi field có generationMethod
client.begin_create_analyzer(analyzer_id="my-analyzer", analyzer=analyzer_definition)
client.begin_analyze(analyzer_id="my-analyzer", ...)
client.delete_analyzer(analyzer_id="my-analyzer")              # dọn tài nguyên test

3. Dễ nhầm với service khác

Cặp dễ nhầmPhân biệt
Document Intelligence vs Content UnderstandingDI = chỉ document (PDF/ảnh form). CU = đa phương thức (document + audio + video + image) chung 1 API. Đề có audio/video → CU, không phải DI.
prebuilt-layout vs prebuilt-invoice/idDocumentLayout = cấu trúc chung (trang/đoạn/bảng/toạ độ), không field nghiệp vụ. prebuilt-invoice/idDocument = field chuẩn hoá cho loại tài liệu cụ thể + confidence.
prebuilt vs custom modelprebuilt = dùng ngay (hoá đơn/ID/receipt...). Custom = train trên mẫu form riêng của bạn khi prebuilt không khớp.
extract vs generate vs classify (CU)extract = lấy giá trị có trong tài liệu. generate = model suy luận/tóm tắt ra giá trị mới. classify = gán nhãn/loại.
Form Recognizer (tên cũ)Form Recognizer = tên cũ của Document Intelligence; SDK cũ azure-ai-formrecognizer. Đề/đáp án nhắc Form Recognizer = ngữ cảnh cũ.
Document Intelligence vs Image Analysis READDI = cấu trúc + field tài liệu (bảng, key-value). Image Analysis READ = OCR chữ thuần trong ảnh. Đề "bảng/field hoá đơn" → DI; "đọc chữ trên biển hiệu" → READ.

4. Exam tips & bẫy

  • Đề nói "trích bảng + cấu trúc + toạ độ từ PDF" → prebuilt-layout.
  • Đề nói "lấy field chuẩn (VendorName/Total) có độ tin cậy" → prebuilt-invoice (hoặc prebuilt-idDocument cho CMND/hộ chiếu), đọc .confidence.
  • Đề nói "mẫu form riêng của công ty, prebuilt không khớp" → custom model (DI) hoặc custom analyzer (CU).
  • Đề nói "phân tích audio/video/ảnh + tài liệu thống nhất một dịch vụ" → Content Understanding (DI không làm được audio/video).
  • Đề nói "định nghĩa field tự do, có field do model sinh ra" → CU custom analyzer, field kiểu generate; field có sẵn → extract; gán loại → classify.
  • Đề nói "Form Recognizer" trong đáp án = dấu hiệu tên cũ; service hiện tại là Document Intelligence.
  • Mọi call đều long-running → dùng poller (begin_analyze_document / begin_analyze), nhớ .result().
  • Dọn tài nguyên test: xoá custom analyzer/model sau khi thử (delete_analyzer).
