1. Tóm tắt

  • Resource hierarchy: Management Group → Subscription → Resource Group → Resource. RBAC gán ở cấp nào thì thừa kế xuống dưới.
  • RBAC = Principal + Role + Scope. Principal (user / group / service principal / managed identity) được gán Role tại Scope.
  • Managed Identity (MI): danh tính do Azure quản lý, không có secret, chỉ chạy trên Azure. Là cách keyless được khuyến nghị.
  • Service Principal (SP): app registration + client secret/cert; chạy mọi nơi (CI/CD, on-prem) nhưng phải giữ secret.
  • Keyless (Entra ID): thay API key bằng DefaultAzureCredential; cần principal có đúng data-plane role nếu không → 401/403.

2. Cú pháp cần nhớ

# Keyless — thứ tự thử của DefaultAzureCredential:
#   EnvironmentCredential -> ManagedIdentity -> AzureCli -> ...
from azure.identity import DefaultAzureCredential
credential = DefaultAzureCredential()

# Gán RBAC bằng code (control plane):
from azure.mgmt.authorization import AuthorizationManagementClient
client.role_assignments.create(
    scope, role_assignment_name=,
    parameters={"role_definition_id": role_def_id,
                "principal_id": principal_id,
                "principal_type": "ServicePrincipal"})   # nên set để tránh PrincipalNotFound

# Service Principal (ngoài Azure):
from azure.identity import ClientSecretCredential
credential = ClientSecretCredential(tenant_id, client_id, client_secret)

3. Bảng built-in roles hay dùng (khi nào dùng)

4. Dễ nhầm

Cặp dễ nhầmPhân biệt
Managed Identity vs Service PrincipalCả hai principal_type='ServicePrincipal'. MI: không secret, chỉ trên Azure. SP: có secret, chạy mọi nơi.
System-assigned vs User-assigned MISystem: gắn 1 tài nguyên, xoá theo tài nguyên. User: độc lập, chia sẻ nhiều tài nguyên.
Control plane vs Data planeTạo deployment = control (actions). Gọi model = data (dataActions). Có quyền control chưa chắc gọi được inference.
Azure AI Developer vs Foundry UserVới Foundry project mới dùng Foundry User; đừng chọn Azure AI Developer (ngữ cảnh hub cũ).

5. Exam tips & bẫy

  • Đề nói "app chạy trên Azure, không muốn quản lý secret" → Managed Identity (ưu tiên system-assigned nếu 1 tài nguyên, user-assigned nếu dùng chung).
  • Đề nói "app on-prem / pipeline CI-CD ngoài Azure cần truy cập Azure" → Service Principal (client secret/cert).
  • Đề nói "least privilege để đọc tài liệu cho RAG" → Search Index Data Reader (không phải Search Service Contributor — role đó không đọc được data).
  • Gặp lỗi 401/403 khi keyless → thiếu data-plane role đúng cho principal, không phải lỗi code.
  • Chọn scope thấp nhất đủ dùng (resource > resource group > subscription) — least privilege.
  • PrincipalNotFound khi tạo role assignment trên principal mới → set principal_type (chờ nhân bản Entra).
