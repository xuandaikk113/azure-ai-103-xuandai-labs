Review 04 · Agent Conversation Management

Quản lý trạng thái hội thoại: stateless thủ công vs Conversations/threads server vs previous_response_id vs Agent Framework thread vs memory provider + context compaction. Ôn nhanh + bẫy thi.

Conversation stateThreadsprevious_response_idMemory

1. Tóm tắt

  • 5 cách giữ ngữ cảnh, từ nhẹ client đến bền server: (1) tự quản messages[] stateless; (2) Conversations API server-managed; (3) previous_response_id (Responses chaining); (4) Agent Framework thread (serialize/resume); (5) memory provider + context compaction.
  • Stateless (04/01): client giữ TOÀN BỘ lịch sử, phải gửi lại mỗi lượt → tốn token khi dài; cần tự trim/nén.
  • Conversations API (04/02): tạo conversations.create(), add message, rồi responses.create(conversation=conv.id) — server tự nhớ, khỏi gửi lại lịch sử. (Thay cho Threads/Runs của Assistants cũ.)
  • previous_response_id (04/03): nối lượt chỉ bằng id của response trước — state nhẹ server-side, không cần tạo conversation object. Bỏ tham số này → model không nhớ.
  • Agent Framework thread (04/04): state tách khỏi agent; serialize ra JSON/file để resume phiên sau. (Thay ChatHistory của Semantic Kernel.)
  • Memory (04/05): fact bền theo user (vd FoundryMemoryProvider); context compaction = tóm tắt lượt cũ để giảm token mà giữ ý chính.

2. Cú pháp cần nhớ

# (1) Stateless — client tự giữ & gửi lại toàn bộ:
messages = [{"role":"system","content":"..."}]
messages.append({"role":"user","content":q})
messages = trim_history(messages)                       # giữ system + N lượt gần nhất
r = client.chat.completions.create(model=dep, messages=messages)
messages.append({"role":"assistant","content":r.choices[0].message.content})

# (2) Conversations API — server giữ lịch sử:
conv = oai.conversations.create()
oai.conversations.items.create(conversation_id=conv.id,
    items=[{"type":"message","role":"user","content":q}])
resp = oai.responses.create(model=dep, conversation=conv.id)   # khỏi gửi lại
oai.conversations.delete(conversation_id=conv.id)

# (3) previous_response_id — state nhẹ, không cần conversation object:
r1 = client.responses.create(model=dep, input="...")
r2 = client.responses.create(model=dep, input="...",
                             previous_response_id=r1.id)  # bỏ -> KHÔNG nhớ

# (4) Agent Framework — serialize thread/state để resume:
r = await agent.run(q)
json.dump(history, f)          # lưu ra file
# phiên sau: load lại history -> chạy tiếp

# (5) Memory + compaction:
#   - ghi fact user (bền qua phiên) rồi nạp vào system message
#   - compact: nhờ model "tóm tắt hội thoại sau trong 1-2 câu" -> thay lịch sử dài

3. Dễ nhầm với service khác

Cặp dễ nhầmPhân biệt
previous_response_id vs Conversations APIprevious_response_id = nối chuỗi tuyến tính bằng id, không có object quản lý. Conversations = object (conv.id) chứa nhiều item, add message độc lập, query/xoá được. Đề "quản lý phiên nhiều message, nhiều người/kênh" → Conversations.
previous_response_id vs manual history (stateless)Chaining = server giữ, chỉ gửi input mới. Manual = client gửi cả messages[] mỗi lượt (tốn token, nhưng toàn quyền kiểm soát/cắt). Đề "giảm token, khỏi gửi lại lịch sử" → previous_response_id.
Conversations (Responses) vs Threads/Runs (Assistants cũ)Assistants API dùng Threads + Runs (queued→in_progress→completed). Chuẩn mới hợp nhất về Conversations + Responses. Đề nhắc runs.create/poll run = ngữ cảnh API cũ.
Memory vs context compactionMemory = kiến thức bền theo user, chọn lọc, dùng lại nhiều phiên (fact/preference). Compaction = nén lịch sử hội thoại hiện tại thành tóm tắt để vừa context window. Khác mục đích: nhớ lâu vs gói gọn.
Agent Framework thread vs Foundry ConversationsThread Agent Framework = state code-first, serialize/resume phía bạn. Conversations = state do Foundry server giữ. Đề "portable, lưu file, resume offline" → Agent Framework thread.

4. Exam tips & bẫy

  • Đề nói "không gửi lại toàn bộ lịch sử, state nhẹ" → previous_response_id (Responses chaining).
  • Đề nói "server giữ phiên, nhiều message, xoá/quản lý được" → Conversations API.
  • Đề nói "toàn quyền kiểm soát ngữ cảnh / cắt-nén tay" → stateless messages[].
  • Đề nói "nhớ sở thích người dùng qua nhiều phiên" → memory provider, KHÔNG phải fine-tune.
  • Đề nói "hội thoại quá dài, vượt context" → context compaction (tóm tắt) hoặc trim, không phải tăng model.
  • chat.completions KHÔNG có previous_response_id — muốn nhớ phải tự gửi lại messages hoặc dùng Conversations.
  • Stateless: luôn giữ system message khi trim; chỉ cắt các lượt user/assistant cũ.
  • Bỏ previous_response_id/conversation = model mất trí nhớ lượt trước (lỗi logic, không phải lỗi quyền).
